## 1. תקציר מנהלים

OctoBankX (כספת) היא פלטפורמת ווב מלאה המבצעת אוטומציה של הורדה יומית של קבצי דפי חשבון ממספר מוסדות פיננסיים ישראליים באמצעות SFTP מאובטח. היא מחליפה תהליכים ידניים מועדים לשגיאות בזרימת עבודה אמינה, ניתנת לביקורת ואוטומטית.

**יכולות מרכזיות:**

- הורדות SFTP אוטומטיות יומיות עם לוגיקת ניסיון חוזר
- לוח בקרה לניטור בזמן אמת עם תרשימים ומדדים
- מסלול ביקורת מלא לכל ניסיון הורדה
- תצורת מפענח וכללי מיפוי עמודות לכל בנק
- ממשק ווב רספונסיבי לנייד
- ממשק API מבוסס REST JSON לאינטגרציה עם מערכות ERP/BI
- תמיכה מלאה בעברית ובאנגלית עם פריסת RTL

## 2. הצורך העסקי

ארגונים המנהלים חשבונות בנק מרובים אצל מספר בנקים ישראליים מתמודדים עם אתגרים תפעוליים יומיים:

| אתגר | השפעה |
|------|--------|
| **הורדות ידניות יומיות** | אנשי כספים מבלים 45–90 דקות ביום בהתחברות לשרתי SFTP של בנקים והורדת קבצים |
| **חוסר עקביות בטיפול בקבצים** | שמות קבצים, מבנה תיקיות ונהלי שמירה משתנים בין עובדים |
| **היעדר מסלול ביקורת** | אין תיעוד מה הורד, מתי, או על ידי מי |
| **כשלים שקטים** | הורדה שנכשלה עלולה לא להתגלות עד שהנתונים חסרים בעיבוד החשבונאי |
| **בעיות מדרגיות** | הוספת בנק או חשבון חדש מחייבת נהלים חדשים והדרכת צוות |

## 3. סקירת הפתרון

OctoBankX מבצעת אוטומציה של כל זרימת העבודה:

```
                     ┌─────────────────────────────────┐
                     │           OctoBankX              │
   ╔═══════════╗     │  ┌──────────┐  ┌─────────────┐  │     ╔══════════════╗
   ║  שרת SFTP ║────▶│  │ משימת   │  │   מעקב     │  │────▶║  ERP / BI /  ║
   ║  של הבנק  ║     │  │ הורדה   │  │  סטטוס     │  │     ║  חשבונאות   ║
   ╚═══════════╝     │  └──────────┘  └─────────────┘  │     ╚══════════════╝
                     │  ┌──────────────────────────┐   │
                     │  │   ממשק ווב + נייד + API  │   │
                     │  └──────────────────────────┘   │
                     └─────────────────────────────────┘
```

**ערך שנוצר:**

| מדד | לפני OctoBankX | עם OctoBankX |
|------|----------------|---------------|
| מאמץ הורדה יומי | 45–90 דקות/יום | 0 דקות (אוטומטי לחלוטין) |
| זמן גילוי כשל | שעות עד ימים | מיידי (מייל + לוח בקרה) |
| כיסוי ביקורת | חלקי | 100% |
| הוספת בנק חדש | נהלים חדשים + הדרכה | מילוי טופס בממשק |
| זמינות נתונים לעיבוד | עיכוב של שעות | אוטומטי — מוכן ב-06:00 |

## 4. סיכום תכונות

### תכונות ליבה

| תכונה | תיאור |
|--------|--------|
| **ניהול בנקים** | רישום בנקים עם פרטי חיבור SFTP, הקצאת מפענח, כלל מיפוי עמודות ותיקיית יעד |
| **הורדות אוטומטיות** | הורדת SFTP יומית מתוזמנת עבור כל הבנקים הרשומים |
| **מאזין דוא״ל** | ניטור תיבת דואר ייעודית (IMAP/POP3) לקבלת קבצי דפי חשבון משולחים מאושרים |
| **ניהול שולחי דוא״ל** | תחזוקת רשימת כתובות דוא״ל מאושרות עם שיוך לבנק וסטטוס פעיל/לא פעיל |
| **מחזור חיי הורדה** | מעקב סטטוס מלא: `ממתין → פעיל → הצלחה / כישלון` |
| **לוגיקת ניסיון חוזר** | ניסיון חוזר אוטומטי הניתן להגדרה במקרה כישלון |
| **פענוח קבצים** | מפענחים ניתנים לחיבור (לאומי, פועלים, דיסקונט, בינלאומי) עם כללי עמודות הניתנים להגדרה |
| **דיווח שגיאות** | לכידת שגיאות מפורטת לכל הורדה עם התראות מייל |
| **מסלול ביקורת** | היסטוריה מלאה של כל ניסיון הורדה עם שמירה של 90 יום |

## 7. מבנה מסד הנתונים

### `banks` — בנקים

שומר פרטי חיבור SFTP ותצורת פענוח לכל מוסד פיננסי.

| עמודה | סוג | הערות |
|-------|-----|-------|
| `id` | integer | מפתח ראשי |
| `name` | string | ייחודי, נדרש |
| `sftp_host` | string | נדרש |
| `sftp_port` | integer | ברירת מחדל: 22 |
| `sftp_remote_path` | string | ברירת מחדל: `/` |
| `sftp_username` | string | שם משתמש SFTP |
| `sftp_password` | string | סיסמת SFTP |
| `ruler` | text | כללי מיפוי עמודות לפענוח קבצים |
| `parser` | string | שם כיתת מפענח (למשל `LeumiParser`) |
| `target_folder` | string | תיקיית יעד מקומית |
| `created_at` | datetime | |
| `updated_at` | datetime | |

### `downloads` — הורדות

רשומה אחת לכל בנק ליום; עוקבת אחר מחזור החיים המלא של כל הורדת דף חשבון.

| עמודה | סוג | הערות |
|-------|-----|-------|
| `id` | integer | מפתח ראשי |
| `bank_id` | integer | מפתח זר → `banks.id`, נדרש |
| `date` | date | תאריך דף חשבון, נדרש |
| `status` | string | `pending` / `running` / `success` / `failed` |
| `error_message` | string | מתמלא בכישלון |
| `file_path` | string | נתיב מקומי לקובץ שהורד בהצלחה |
| `started_at` | datetime | מתי החלה העברת ה-SFTP |
| `completed_at` | datetime | מתי ההעברה הסתיימה |
| `created_at` | datetime | |

**מחזור חיי הורדה:**

```
[נוצר] → ממתין → פעיל → הצלחה
                      ↘ כישלון
```

### `settings` — הגדרות

מאגר מפתח-ערך לתצורה מערכתית.

| עמודה | סוג | הערות |
|-------|-----|-------|
| `id` | integer | מפתח ראשי |
| `key` | string | ייחודי, נדרש |
| `value` | string | |
| `description` | string | רמז קריא |
| `updated_at` | datetime | |

### `email_senders` — שולחי דוא״ל

מחזיקה את רשימת כתובות הדוא״ל המאושרות שמהן המערכת מקבלת קבצי דפי חשבון.

| עמודה | סוג | הערות |
|-------|-----|-------|
| `id` | integer | מפתח ראשי |
| `sender_name` | string | תווית תיאורית, נדרש |
| `sender_email` | string | כתובת דוא״ל ייחודית, נדרש |
| `bank_id` | integer | מפתח זר → `banks.id` (מחיקה מדורגת) |
| `active` | boolean | ברירת מחדל: `true` |
| `created_at` | datetime | |
| `updated_at` | datetime | |

### הורדות

| `GET` | `/api/v1/downloads` | רשימת הורדות (ניתן לסנן לפי `status`, `bank_id`, `date`; תומך ב-`limit`/`offset`) |

## 11. משימות רקע ותזמון

### DownloadJob

למשימה היומית שני שלבים:

**שלב 1 — הכנסה לתור:** לכל בנק במערכת, יוצרת רשומת `Download` עם `status: 'pending'` עבור התאריך הנתון. בנקים שכבר יש להם רשומת הורדה לאותו תאריך מדולגים (אידמפוטנטי).

**שלב 2 — ביצוע:** מעבד את כל הרשומות `pending`:

1. מגדיר `status = 'running'` ומחתים `started_at`
2. מתחבר לשרת ה-SFTP של הבנק באמצעות `SftpHelper`
3. מוריד את קובץ דף החשבון
4. בהצלחה: מגדיר `status = 'success'`, שומר `file_path`, מחתים `completed_at`
5. בכישלון: מגדיר `status = 'failed'`, שומר `error_message`, מחתים `completed_at`

### לוח זמנים

המתזמן פועל באמצעות `rufus-scheduler` ב-`config.ru`. ביטוי ה-cron מוגדר כברירת מחדל ל-`0 6 * * *` (כל יום ב-06:00), ניתן להגדרה באמצעות משתנה הסביבה `JOB_SCHEDULE` או הגדרת `job_schedule`.

### EmailListenerJob

משימת מאזין הדוא״ל מנטרת תיבת דואר ייעודית לקבלת קבצי דפי חשבון משולחים מאושרים:

1. מתחברת לשרת הדוא״ל המוגדר באמצעות IMAP או POP3
2. מאחזרת הודעות שלא נקראו
3. לכל הודעה, בודקת האם כתובת השולח נמצאת בטבלת `email_senders` ופעילה
4. אם מאושרת, מחלצת את כל הקבצים המצורפים מסוג CSV/Excel/ZIP
5. שומרת קבצים מצורפים בתיקיית ההורדות של הבנק המשויך
6. יוצרת רשומת `Download` עם `status: 'success'`
7. מסמנת את המייל כנקרא (IMAP) או מוחקת אותו (POP3)

המשימה רצה בתדירות המוגדרת על ידי `email_check_interval` (ברירת מחדל: 5 דקות).

### הפעלות ידניות

- **ממשק ווב:** לחץ על **הרץ הורדות עכשיו** בלוח הבקרה או בדף ההורדות
- **שורת פקודה:** `bundle exec rake jobs:run`
- **API:** `POST /api/v1/downloads` להכנסת בנק בודד לתור
